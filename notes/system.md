# ClassicSystem

Owned additions: `modules/ClassicSystem.bui`, `tests/classic_system_test.bui`, and this note. Foundation: `Import RBFoundation`. The 18 installed Xojo module files were byte-compared with `/usr/share/buoy/packages/Xojo-1.0.0.buipkg`; all matched. No dependency/toolchain sources were edited.

## Integration and supported behavior

The entry module needs `Public Import ClassicSystem`. **No ordinary exported globals require selective `Public Import`.** Public extensions and classes flow through the plain import. Add/package the existing **processkit** dependency alongside Xojo and its dependencies (including zip). ProcessKit's installed module matched the repository module when inspected; the isolated test used `packages/processkit-0.1.0.buipkg`.

- `Timer.Mode` reads/writes the existing RunMode state, validates 0..2, and maps `Timer.ModeOff = 0`, `Timer.ModeSingle = 1`, `Timer.ModeMultiple = 2`. Off stops, Single sets Count=1 and starts, Multiple sets Count=-1 and starts. RunMode/Enabled assignments share that state. Constants are zero-argument Shared extensions: rewrite instance constant access such as `timer1.ModeSingle` to `Timer.ModeSingle` (Buoy rejects instance access to the Shared extension even if an instance extension also exists).
- **Plain Timer limitation:** Mode reports the last shim assignment, not actual running state. Native Start/Stop and automatic completion cannot be observed. Rewrite the source type to **ClassicTimer** to observe one-shot completion: its NotifyTick sets Off before calling the Action delegate. Configure it through Mode/RunMode/Enabled, and call Super.NotifyTick from further overrides. Direct Count changes, native Start/Stop, and manually calling PerformTick bypass native lifecycle semantics. Action remains Buoy's no-argument delegate property; this does not add a legacy Action event.
- `Shell.ErrorCode` aliases native LastExitCode. Native Shell remains a persistent shell, with its existing semantics.
- Rewrite source **Shell to ClassicShell** for fresh processes on every Execute. Modes 0/1/2, Result, draining ReadAll, ErrorCode/ExitCode, IsRunning, Write/WriteLine (mode 2), Close, DataAvailable and Completed operate over ProcessKit pipes and real exit status. Async polling runs through a native 10ms Timer or explicit main-thread Poll. Completed fires once for modes 1/2 after exit and both pipe EOFs, including Close; synchronous mode emits no events. Close/destruction terminate the owned process group/job. Windows TimeOut defaults to 2000, accepts -1, and reports -2 on timeout; Unix ignores TimeOut as documented by Xojo.
- Existing `UDPSocket.RouterHops` and `SendToSelf` getters are retained; new Assigns setters update the actual MulticastTTL/MulticastLoopback properties before or after binding. TTL validates 0..255.
- Rewrite source **UDPSocket to ClassicUDPSocket** for Port/Connect/IsConnected. Port configures the local bind, reflects the OS-assigned ephemeral port after Connect, and cannot change while bound. Connect is idempotent while bound. API 1 Write(address,data) sends to Port, not the last sender's source port. Native socket events remain inherited; no fake SendComplete/event queue was added.
- `System.IsFunctionAvailable(name,library)` uses dlopen/dlsym on Unix and LoadLibraryW/GetProcAddress on Windows, with UTF-16 Windows library names. Successful library handles remain loaded and are mutex-protected; failures retry. Empty/NUL-bearing names return False. Unix `c` maps to libc; macOS `System` also maps to libSystem. Other names/paths use the native loader verbatim.
- `System.Log(Integer,String)` supports **POSIX syslog priorities 0..7 only**, via `/usr/bin/logger -p user.<severity> -- message`, using ProcessKit argv rather than shell interpolation. This preserves severity and literal percent signs/metacharacters. The direct syslog Declare cannot link against Buoy's installed Linux libc stub (syslog is absent), and Optional Declare forbids variadic signatures; no toolchain was patched. Logger execution failures throw. Windows throws UnsupportedOperationException, because debugger output is not Windows Event Log. **Xojo LogLevel* constants and their platform-specific literal values are not implemented/claimed.** This is a limited integer-priority adapter, not complete System.Log compatibility.

## Explicit limits and remaining work

ClassicShell decodes stdout and stderr independently as UTF-8, preserving incomplete scalars across polls and ReadAll calls before merging decoded text. Relative ordering between the two streams is not preserved. Invalid/truncated UTF-8 and NUL output raise EncodingException and release the owned process; binary output needs a Bytes-based API. It has no PTY, backend/arguments/PID/canonical options, or two-argument Execute overload. Execute while a command is active and Mode changes while active throw. Retain async instances until completion. Descendants holding inherited pipes can delay completion; Close terminates the owned tree. Windows timeout and native behavior outside Linux have compiler checks only. Packaging must provide matching ProcessKit runtime binaries; the current package does not carry every arm64 runtime.

ClassicUDPSocket supports literal IPv4 addresses. Close is terminal in native Buoy; create a new instance to reconnect. Bind/receive errors retain native exception/event types. Xojo's boolean JoinMulticastGroup result, DNS, selected network interfaces, queue-count properties and SendComplete remain core/adapter work.

Symbol lookup is an exported-address availability test, not proof of a function ABI or callable code (dlsym/GetProcAddress can also return data symbols). It caches library handles, not individual symbol results. It does not expand macOS framework shorthand or mirror all Declare library search rules. Linux dlopen/dlsym bind through libc, requiring glibc 2.34+; the current host supports this. Cross-target checks do not verify foreign linking or runtime loader behavior.

Logging requires `/usr/bin/logger`, incurs subprocess overhead, uses its default tag/metadata, and is best effort: successful exit does not prove durable journal delivery. Large messages may meet logger/OS size limits. A native logger adapter plus verified Xojo LogLevel values and a Windows Event Log implementation remain necessary for full compatibility.

**Serial investigated, not implemented:** the bundled opt-in serialio package exposes SerialPort/SerialConnection, real data/error/closed events, DTR/RTS and byte pipes. Legacy Serial.Baud is an index (Baud9600=8, Baud115200=14), not the baud integer accepted by SerialConfig. Blind aliases would configure the wrong hardware. A faithful adapter needs explicit verified legacy option mappings, error-code translation, reset/reopen behavior, and real buffered LookAhead/BytesAvailable; native line-change notifications, CTS/DCD/DSR/RI, break/flush/XmitWait controls are not all exposed by Serialio. No stored-only Serial facade was added. Further work needs a PTY fixture and physical-line tests where applicable.
